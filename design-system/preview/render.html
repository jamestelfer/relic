I want to refactor the parser. Right now everything comes out as a generic Block with a Type string field, and the renderer does switch b.Type in three different places. Let's introduce typed content blocks — concrete structs per kind — and use a discriminated union instead.

assistant14:23 · 1m later

Good cut. I'll define parser.ContentBlock as an interface, then concrete types: TextBlock, ToolUseBlock, ToolResultBlock, ThinkingBlock, RawBlock. The decoder dispatches on the JSON type tag once, and downstream code uses type switches.

The interface is minimal — a single marker method blockKind() string — so concrete types don't need to import the interface package. Each struct carries only the fields it needs: TextBlock holds Text string; ToolUseBlock carries ID, Name, and Input json.RawMessage; ToolResultBlock has ToolUseID, Content []ContentBlock, and IsError bool; ThinkingBlock wraps Thinking string and Signature string; RawBlock preserves the original JSON for forward compatibility.

The decoder is a single UnmarshalContentBlock(data []byte) (ContentBlock, error) function that peeks the type field and dispatches to the right concrete unmarshaller. No string constants leak past the parser boundary — downstream code does a type switch on the interface.

Starting with the type definitions in internal/parser/blocks.go.
